# 代码规范

## 基本原则

- 改动应形成可运行的完整用户流程。领域模型、Host、IPC、WinUI 或 CLI、持久化和测试按实际需要同步更新。
- 不保留没有应用入口的算法、接口、Schema、项目或占位实现。删除功能时一并清理依赖、测试和文档。
- 优先扩展现有类型和调用链。只使用一次且没有独立语义的逻辑不提取为新层。
- 注释用于解释代码本身无法表达的约束和设计原因，不记录改动过程、历史方案或待办事项。
- 用户可见行为以原始数据和实际运行结果为依据。串口 RX/TX 原始字节先进入事件与会话，再派生文本、HEX、波形和协议结果。

## 项目边界

依赖保持以下方向：

```text
Domain
  ↑
Application / Protocols / Sessions
  ↑
Serial.Windows / Storage / IPC / Host
  ↑
WinUI / CLI
```

- `SerialWorkbench.Domain` 只定义跨层共享的领域模型，不依赖界面、存储或 Windows 串口实现。
- `SerialWorkbench.Application` 承担事件日志、写入租约等应用级协调逻辑。
- `SerialWorkbench.Serial.Windows` 持有串口句柄、读写循环和连接内状态。
- `SerialWorkbench.Host` 组合串口、会话、工作区和 RPC 服务。需要独占串口状态或跨客户端一致性的操作在 Host 中完成。
- `SerialWorkbench.Ipc` 只提供版本化 RPC 契约和客户端连接，不包含界面行为。
- `SerialWorkbench.WinUI` 通过 IPC 使用 Host，不引用 `Serial.Windows`、`Sessions` 或 `Storage`。
- `SerialWorkbench.Cli` 与 WinUI 共用 RPC 契约，不复制 Host 中的业务流程。

## C#

### 格式与命名

- 遵循根目录 `.editorconfig`，使用 UTF-8、CRLF 和文件末尾换行。
- C# 使用四空格缩进、文件范围命名空间和 K&R 之外的独立大括号行。
- 类型、公开成员和枚举项使用 PascalCase；局部变量、参数和私有字段使用 camelCase。
- 异步方法使用 `Async` 后缀。事件使用描述已经发生或请求发生的名称，如 `SendRequested`、`SessionSelected`。
- 能从右侧清楚得知类型时使用 `var`。空集合使用集合表达式 `[]`。
- 简单映射优先使用表达式成员和 switch 表达式；分支较多或包含资源管理时使用完整方法体。
- 数值、时间、路径和编码转换应显式使用对应类型及文化设置，不依赖当前区域的隐式解析行为。

### 类型与数据

- 跨项目传递的不可变数据使用 `record`，带行为和可变状态的对象使用 `class`。
- 原始串口数据使用 `byte[]`、`ReadOnlyMemory<byte>` 或 `ReadOnlySpan<byte>`，不以格式化 HEX 字符串替代原始字节。
- 公共集合返回只读接口，如 `IReadOnlyList<T>`；需要界面增量更新时使用 `ObservableCollection<T>`。
- 可空状态通过 nullable 类型表达。项目启用 nullable，不使用 null-forgiving 运算符掩盖未处理状态。
- 固定范围在入口处校验，并抛出带参数名的 `ArgumentOutOfRangeException`。缺失资源使用 `KeyNotFoundException`，无效数据使用 `InvalidDataException`，状态冲突使用 `InvalidOperationException`。

### 异步与资源

- I/O 方法接收并传递 `CancellationToken`。超时使用关联的 `CancellationTokenSource` 表达。
- 类库异步调用使用 `ConfigureAwait(false)`；WinUI 事件处理保留界面上下文。
- `IDisposable` 和 `IAsyncDisposable` 资源分别使用 `using`、`await using`，锁和信号量必须在 `finally` 中释放。
- `async void` 只用于 XAML 或 .NET 事件处理程序。其余异步流程返回 `Task` 或 `ValueTask`。
- 串口写入必须经过连接写入租约。需要读取当前请求响应的操作应先建立 RX 订阅，再发送请求，并在 Host 内处理分块、超时和取消。
- 后台读取循环只捕获能够处理的设备和 I/O 异常。取消、设备故障和协议错误保持不同语义。

### 异常与界面反馈

- 不使用空 `catch` 隐藏失败。仅在资源关闭或取消路径中忽略已经预期且无法继续处理的异常。
- Host 和类库保留具体异常语义；WinUI 在用户操作边界将异常转换为 `InfoBar` 或对话框信息。
- 成功、警告和错误使用对应的 `InfoBarSeverity`。按钮在异步操作期间禁用，并在 `finally` 中恢复。
- 用户可见文字使用自然、简短的中文。日志、内部来源标识和协议字段保持稳定的程序化名称。

## WinUI 与 XAML

- 使用 Windows App SDK 原生控件和主题资源。常规界面不自行绘制按钮、列表、导航或设置卡片。
- `MainWindow` 负责导航外壳、全局连接状态和跨页面协调；页面负责自身控件状态、输入解释和结果呈现。
- 页面通过事件向 `MainWindow` 请求操作，不从页面直接访问 Host 客户端或串口实现。
- XAML 使用两空格缩进。重复的稳定几何放入共享资源；单个页面特有布局保留在页面中。
- 响应式布局使用 `VisualState`，由页面实际内容宽度切换。阈值依据页面结构设置，不要求所有页面共用同一阈值。
- 窄窗口应重新排列内容并利用可用高度，不以缩小字体、隐藏必要字段或固定整页高度处理。
- 图标使用系统图标并匹配动作语义。状态图标与文字分开表达，不能只依赖颜色传递状态。
- 列表中的长报文保持单行省略，并通过工具提示或复制操作提供完整内容，避免行高随数据变化。
- 高对比度使用系统颜色；Light 和 Dark 优先使用控件或第三方组件提供的内置主题。

## RPC、协议与持久化

- RPC 契约变更应同步更新接口、Host 实现和客户端调用。破坏兼容性的变更调整主版本，向后兼容的新增调整次版本。
- 一个请求需要串口独占、响应关联或超时控制时，由 Host 提供完整 RPC 操作，不由客户端轮询事件拼装事务。
- 协议解析先验证最小长度、CRC、地址、功能码和完整帧长，再读取字段。异常响应保留协议异常码。
- 串口读取块不等同于协议帧。解析器必须支持一次响应分成多个读取块，也支持一个读取块包含更多数据。
- 会话始终保存原始事件。派生的文本、HEX、波形或协议结果不能覆盖原始数据。
- 应用管理的数据位于可执行文件旁的 `data/` 或所选工作区。新增持久化文件应沿用现有路径模型和 JSON 序列化方式。
- SQLite 操作使用参数化查询、明确事务和异步资源释放。会话文件应保持可独立读取和迁移。

## 测试

- 测试名称描述稳定行为或架构边界，不描述实现步骤。
- 协议测试使用公开已知向量或在测试中明确构造的完整帧，覆盖正常响应、异常响应、CRC、长度和边界值。
- 存储测试验证真实文件和数据库内容，包括事件顺序、原始字节、工作区路径和生命周期。
- 架构测试只约束必须长期成立的依赖方向。不要锁定完整包清单、具体控件集合或暂时的文件数量。
- 每项功能测试其实际入口和跨层结果。没有应用入口的独立算法测试不能证明功能已经完成。
- 测试产生的文件放在测试产物目录中，名称包含随机标识，避免测试之间共享可变状态。

## 文档

- README 说明用户当前能够运行的功能、入口和构建方式；系统结构和产品语义分别写入 `docs/architecture.md` 与 `docs/design.md`。
- 文档只描述当前实现。删除功能时同步删除对应目录、命令、Schema 和能力说明。
- 不写已经被拒绝的方案、实现阶段、临时状态或从代码和版本控制中即可得到的改动清单。
- 示例命令应可复制，路径、程序名、参数和产物目录与当前脚本保持一致。

## 构建与提交

- 依赖版本集中在 `Directory.Packages.props`，项目通用编译属性集中在 `Directory.Build.props`。
- 使用项目脚本执行完整流程：`eng/build.ps1` 格式化并构建 Release，`eng/test.ps1` 执行完整构建和测试，`eng/publish.ps1` 生成便携发布目录。
- 不手工修改生成产物。发布内容由项目文件和发布脚本生成，并保留 WinUI 的 PRI、XBF 和 Windows App SDK 文件。
- 一个提交只表达一个完整意图，相关代码、测试和文档放在同一提交中。
- 提交标题使用简短中文动宾结构，如“实现会话管理”“修正串口默认选择”“清理未接入的任务与终端模块”。
- 标题描述改动带来的作用，不罗列文件或局部语句。没有必要说明的提交不写正文。
