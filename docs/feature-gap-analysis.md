# SerialWorkbench 功能缺口与优化清单

本文档依据当前仓库源码、XAML、Host RPC、串口实现、会话存储、CLI、测试和发布脚本整理。它描述当前实现与完整串口工作台之间的差距，不代表已经实现的功能。

## 当前已经接通的能力

```text
WinUI / CLI
  → Named Pipe + StreamJsonRpc
  → SerialWorkbench.Host
  → SerialConnectionManager
  → System.IO.Ports.SerialPort
  → EventJournal + SessionStore
```

当前可以使用：

- Windows 串口枚举。
- 端口、波特率、数据位、校验、停止位、流控、DTR、RTS。
- 文本和 HEX 发送。
- CR、LF、CRLF 行尾。
- XOR、SUM8、CRC16-Modbus、CRC16-XModem、CRC32 追加。
- RX/TX 实时事件和计数。
- HEX 或文本监视。
- CSV 文本和固定二进制帧波形。
- 固定、递增、随机数据回环检测。
- 回环结果按会话保存，并显示成功状态、差异位置、耗时和吞吐率。
- Modbus 请求构造。
- 手工粘贴 Modbus 响应并解析。
- SQLite 会话记录。
- 工作区切换。
- 会话浏览、预览、完整 CSV 导出、按原始时间间隔回放、删除和资源管理器定位。
- 命名串口连接配置的新建、重命名、删除和应用。
- 交互式串口终端，支持文本、HEX、行尾、历史和响应复制。
- CLI Modbus 读写事务和结构化结果输出。
- Modbus 事务对 TX 回显、无关接收、合法响应、CRC 错误、超时和异常码分别显示。
- Modbus RTU 协议帧查看器和模板文件。
- 工作区自动化发送序列，支持多步骤、延时、重复和取消。
- XMODEM-CRC 文件发送和接收，传输使用独占写入租约。
- CLI 端口枚举、Host 状态、工作区、发送、监视和回环。
- 跟随系统、浅色、深色、高对比度和响应式布局。
- self-contained WinUI 便携发布。

## 一、当前功能中的断点

### 1. Modbus 没有自动请求—响应流程

相关文件：

- `src/SerialWorkbench.WinUI/MainWindow.xaml.cs`
- `src/SerialWorkbench.WinUI/Pages/ModbusPage.xaml.cs`
- `src/SerialWorkbench.Serial.Windows/SerialConnectionManager.cs`
- `src/SerialWorkbench.Modbus/ModbusRtuCodec.cs`

当前发送流程是：

```text
构造请求 → 发送 → 提示“响应见接收页报文流”
```

页面仍要求手工粘贴响应 HEX。缺少：

- 发送前建立 RX 订阅。
- 将响应关联到当前请求。
- 处理一次返回多个块或一个块包含多帧。
- 按功能码确定完整长度。
- 超时。
- CRC 错误。
- 地址和功能码不匹配。
- 异常响应。
- 自动填充响应 HEX 和寄存器列表。
- 显示请求—响应耗时。

完整事务应在 Host/串口层实现，由 RPC 返回结构化结果，不能依赖 WinUI 的普通报文轮询。

### 2. 功能码 06 的解析不正确

读寄存器响应格式是：

```text
地址 功能码 字节数 数据 CRC
```

功能码 06 的成功响应是 8 字节请求回显：

```text
地址 06 寄存器地址 寄存器值 CRC
```

当前 `ParseRegisterResponse` 仍按读寄存器格式解析功能码 06，会把响应中的地址字段误当成字节数。

同时，页面将功能码 06 的寄存器值复用 `Quantity`，而 `Quantity` 的最大值为 125，无法输入完整的 `0–65535` 范围。

需要单独的写单寄存器响应解析和独立的寄存器值输入范围。

### 3. Modbus 页面与协议库支持范围不一致

协议库的 `BuildReadRequest` 支持功能码 01、02、03、04，页面只提供 03、04、06。

尚未支持：

- 读线圈 01。
- 读离散输入 02。
- 写单线圈 05。
- 写多个线圈 0F。
- 写多个寄存器 10。
- 读写多个寄存器 17。
- 广播地址处理。
- 地址扫描。
- 周期轮询。
- 寄存器监视。

第一阶段不必一次覆盖全部功能码，但页面、协议库、测试和文档的支持范围必须一致。

### 4. 多连接事件过滤可能停滞

`HostRpcService.ReadEventsAsync` 先从全局事件中取前 `MaximumCount` 条，再按 `ConnectionId` 过滤。

当其他连接产生大量事件时，当前连接可能长期得不到事件，客户端也不会推进序列号。WinUI 和 CLI 的监视窗口都会受到影响。

应先按连接过滤，再应用数量限制，并返回最早可用序列号或丢失事件数量。

### 5. 慢订阅者可以阻塞串口读取

`SerialConnection.ReadLoopAsync` 向每个订阅通道调用 `WriteAsync`。通道满后，真实串口读取循环会等待慢订阅者。

这可能导致：

- 串口缓冲积压。
- 高速数据丢失。
- 会话记录速度受到 UI 速度影响。
- 协议事务阻塞普通接收。

串口读取、事件持久化和观察者分发应解耦。慢观察者需要独立的丢弃、采样、断开或错误策略。

### 6. 回环检测会丢弃多余字节

回环每轮只取期望长度。如果一次读取返回的数据超过当前轮需要的长度，剩余字节会被丢弃，下一轮不会继续消费。

高速回环、多次迭代或一个读取块包含多个回环结果时会误报失败。订阅消费端需要保留剩余缓冲。

### 7. 回环没有取消和进度

当前回环运行期间：

- 没有取消按钮。
- 没有当前迭代。
- 没有实时发送和接收统计。
- 没有实时速率。
- 没有用户可配置超时。
- 关闭窗口不能主动取消任务。

### 8. 设备拔出后的状态恢复不完整

读取循环可以进入 `Faulted`，但 WinUI 没有完整处理设备拔出：

- 连接按钮不会稳定恢复为“连接”。
- 串口参数不一定重新启用。
- 循环发送不会自动停止。
- 回环任务没有清晰的中止状态。
- 没有自动重连。
- 插回设备后不会按设备身份恢复。

已连接时端口刷新计时器还会停止，设备拔插无法得到完整的 UI 状态更新。

### 9. 会话生命周期与连接生命周期没有对齐

当前会话在第一次事件写入时创建，关闭串口不会结束会话。会话通常要等 Host 退出或切换工作区才完成。

需要明确：

- 连接建立时还是第一条数据时开始会话。
- 关闭单个连接时是否结束会话。
- 多连接是否共用会话。
- Host 异常退出后的状态。
- 重连是否创建新会话。

### 10. 串口设置持久化

普通串口页面偏好保存为最近使用配置，命名连接配置保存到设置目录。当前打开连接时会将页面编码传入 `SerialConnectionOptions.EncodingName`。

## 二、串口工具必需补齐的功能

### 1. 报文筛选和搜索

当前报文页只有暂停、清空、复制全部 HEX 和 HEX/文本切换。

建议增加：

- 只看 RX。
- 只看 TX。
- 按来源筛选。
- 按连接筛选。
- 文本关键字搜索。
- HEX 搜索。
- 时间范围筛选。
- 报文长度筛选。
- 匹配高亮。
- 当前结果数量。
- 跳转到下一条匹配。

### 2. 报文导出

当前已支持从会话页导出当前会话的完整 CSV 原始事件。其他导出形式仍包括：

- TXT。
- HEX。
- CSV。
- JSON。
- JSONL。
- 原始二进制。
- 带时间戳的 TX/RX 日志。
- 当前筛选结果。
- 指定会话。
- 指定时间范围。

CSV 导出保留 UTC 时间、方向、来源、原始 HEX 和字节数，内容来自 SQLite 事件表，不受页面显示数量和文本截断影响。

### 3. 会话回放

当前已支持从会话页按原始事件时间间隔回放到工作台事件流，回放不写入真实串口，也不创建新的会话事件。其他回放形式仍包括：

- 只回放 TX。
- 保留原始时间间隔。
- 固定间隔回放。
- 调整回放倍率。
- 预览模式。
- 回放到指定串口。
- 暂停、继续和停止。
- 回放来源标记。

### 4. 发送历史持久化

当前发送历史只存在内存中，程序退出即丢失。

需要保存：

- 文本或 HEX 内容。
- 格式。
- 编码。
- 行尾。
- 校验算法。
- 配置名称。
- 使用次数和最近使用时间。

### 5. 多条发送队列

单条发送和循环定时器不足以覆盖设备调试。应支持：

- 多条发送项。
- 每条独立文本/HEX。
- 每条独立行尾和校验。
- 每条独立延迟。
- 发送次数。
- 启用/禁用。
- 队列循环。
- 条件等待。
- 收到指定响应后继续。
- 保存、加载、导入和导出。

循环发送和发送队列应由 Host 调度，WinUI 只负责编辑和展示。

### 6. 自动滚动和视图暂停分离

当前暂停会停止 WinUI 事件读取，自动滚动则始终执行。

需要区分：

- 继续后台接收和持久化。
- 暂停界面刷新。
- 暂停自动滚动。
- 用户查看历史时自动暂停滚动。
- 跳到最新。
- 显示未读事件数量。
- 恢复后报告已经被内存日志淘汰的区间。

### 7. 流式文本解码

当前每个 RX 块独立调用 `Encoding.GetString`。UTF-8 或 UTF-16 字符跨读取块时可能出现乱码。

应为每个连接维护持续的文本解码器，原始字节仍作为唯一数据来源保留。

### 8. 串口控制操作

常用控制功能还包括：

- 连接后切换 DTR。
- 连接后切换 RTS。
- 发送 BREAK。
- 清空 RX 缓冲。
- 清空 TX 缓冲。
- 清除错误状态。
- 显示 CTS、DSR、CD、RI。
- RS-485 半双工方向控制。
- RTS 前后延时。

### 9. 设备身份和端口绑定

端口目录已经取得 VID、PID 和 PNP 信息，但页面没有使用。

应支持：

- 显示制造商和设备描述。
- 显示 VID/PID。
- 显示 DeviceInstanceId。
- 按设备身份匹配端口。
- 端口变化后识别同一设备。
- 配置名称和默认配置。
- 连接配置导入导出。

## 七、连接可靠性和多连接

### 自动重连

`ConnectionState` 已包含 `Reconnecting`，但没有实际重连流程。应增加：

- 自动重连开关。
- 重连次数。
- 重连间隔和退避。
- 设备身份匹配。
- 重连成功事件。
- 重连期间的会话策略。
- 手动停止重连。

### 多连接

Host 使用连接字典，理论上支持多连接，但 WinUI 只有一个 `connectionId`。

需要在产品方向上选择：

- 继续保持单连接，并清理多连接歧义；或
- 增加连接列表、独立监视、统一时间线、逻辑角色和独立发送队列。

如果采用多连接，应支持 `DUT`、`DEBUG`、`CONTROLLER`、`LOOPBACK` 等稳定角色，不将任务绑定到易变的 COM 名称。

## 八、性能、数据可靠性和工程问题

### 1. RX 读取与 SQLite 写入耦合

当前 RX 读取循环等待 `SessionStore.AppendAsync` 完成后才继续读取。高波特率连续数据可能受到磁盘写入速度限制。

应使用独立的有界持久化队列，并明确磁盘写入失败、队列满和事件丢失的状态。

### 2. 内存事件和 UI 集合的头部删除

`EventJournal` 使用 `LinkedList`，WinUI 使用 `ObservableCollection`并从头部删除。长时间运行时需要环形缓冲、批量更新或虚拟化列表。

### 3. 事件游标不报告丢失

当 UI 暂停时间过长、内存日志超过容量后，恢复时无法知道中间事件已经被淘汰。需要最早序列号、丢失数量和恢复提示。

### 4. 崩溃日志没有轮转

`data/logs/crash.log`持续追加，没有大小上限、轮转和清理策略。

### 5. 发布脚本会递归清理发布目录

`eng/publish.ps1`通过 `Reset-RepositoryBuildDirectory`清空输出目录。如果目标目录中有便携数据、会话或设置，会被一起删除。

发布应采用临时目录生成程序文件，并保留现有 `data/`，发布失败时也不能破坏旧产物。

### 6. 版本来源尚未统一

当前没有统一的 `Version`、`AssemblyVersion` 和 `FileVersion`来源。清单、程序集、关于页、Host 状态和 Git tag 需要使用同一个正式版本来源。
